# Phase 1.5 — Reliability & Operations Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use the appropriate execution skill (`executing-plans` or `subagent-driven-development`) to implement this plan.

**Goal:** Make the stack survive provider outages, eliminate plaintext secrets, add health monitoring, daily digest, and basic backups.
**Architecture:** Server-side TTS provider chain with health-checked failover. All API keys move to Fly.io secrets. Patch xiaozhi-esp32-server config loader to expand `${ENV_VAR}` references. Add `/healthz` checking LLM/STT/TTS/DB readiness. Nightly backup of `/opt/xiaozhi-esp32-server/data/` to encrypted Backblaze B2 bucket.
**Tech Stack:** Python 3.11, requests, cryptography, Backblaze B2 SDK, Fly.io secrets, GitHub Actions (for daily digest cron).
**Assumptions:**
- Assumes xiaozhi-esp32-server's config loader is patchable in a small, contained way — will NOT work cleanly if config parsing is deeply embedded (will fall back to a wrapper script that does substitution before app launch).
- Assumes Backblaze B2 free tier (10GB) is sufficient — will NOT work indefinitely if voiceprint+memory+logs exceed 10GB (currently far below).
- Runs in parallel with Phase 1; both touch the server image so coordinate via separate branches per phase.

### Task 3: Patch config loader to expand ${ENV_VAR}

**Files:**
- Modify: `~/jarvis-server/Dockerfile`
- Create: `~/jarvis-server/expand_config.py`

**Step 1:** Write a pre-launch script that reads `.config.yaml`, expands `${VAR}` patterns from environ, writes to `.config.yaml.expanded`, and the app reads from there.

`expand_config.py`:
```python
import os
import re
import sys

def expand(src: str, dst: str):
    with open(src) as f:
        text = f.read()
    text = re.sub(r"\$\{([A-Z_][A-Z0-9_]*)\}",
                  lambda m: os.environ.get(m.group(1), ""), text)
    with open(dst, "w") as f:
        f.write(text)

if __name__ == "__main__":
    expand(sys.argv[1], sys.argv[2])
```

**Step 2:** Modify `entrypoint.sh`:
```bash
python /opt/expand_config.py /opt/xiaozhi-esp32-server/data/.config.yaml \
  /opt/xiaozhi-esp32-server/data/.config.yaml.expanded
# Tell the server to use the expanded version
mv /opt/xiaozhi-esp32-server/data/.config.yaml.expanded \
   /opt/xiaozhi-esp32-server/data/.config.yaml
```

**Step 3:** In `.config.yaml.cloud`, replace literal keys with `${ANTHROPIC_API_KEY}` etc.

**Step 4:** Deploy + verify
```bash
fly deploy
fly logs --app jarvis-server | grep -i 'init\|tts\|llm' | tail
```
Expected: no auth errors.
